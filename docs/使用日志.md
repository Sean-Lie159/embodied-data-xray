# 消耗tokens统计

需要考虑，而且现在正是加它的好时机——理由有三个：① 你马上要用真实数据高频实战，**token 消耗 = 你的使用成本**，看不见就管不住；② 它能让你**亲眼看到上一轮讨论的"历史累积"**——每轮的输入 token 会随对话变长而涨，那个数字就是最直观的证据；③ 成本低，SDK 里现成的。

## 原理（通俗版）

每次模型回答完，API 的响应里会带回一份"小票"（usage）：**这轮读了多少字（input_tokens）、写了多少字（output_tokens）**。openai-agents SDK 会把一次运行（包括 agent 循环里每一次内部调用）的小票汇总好，从 `result.context_wrapper.usage` 里就能拿到。

注意一个细节，正好呼应上一个问题：**input_tokens 包含全部对话历史**——所以你会看到第 1 轮输入 2K，第 10 轮输入 20K，这条上涨曲线就是"背着全部历史"的数字化呈现。

## 发给 Code Buddy 的指令

> 增加 token 消耗统计功能（轻量级，一次 commit）：
>
> **1. 数据获取**：`run_turn` 的返回值中增加本轮 usage——从 `result.context_wrapper.usage` 提取聚合的 input_tokens / output_tokens / total_tokens（该字段已汇总 agent 循环内所有 LLM 调用）；MaxTurnsExceeded 等异常路径下 usage 可能缺失，做判空处理（缺失时返回 None 并在注释说明）；
>
> **2. CLI 展示**：每轮回答结束后，以不打扰正文的样式打印一行小字，如 `—— 本轮 token：输入 2,847 / 输出 312（含工具循环 2 次）`；
>
> **3. UI 展示**：每条 agent 回复下方显示本轮 token 小字；侧边栏显示**会话累计**（输入/输出/总 token），累计值存 `st.session_state`，刷新页面清零属预期行为；
>
> **4. （可选，做了更好）config 中增加模型单价表**（如 deepseek-chat 的输入/输出单价，单位 ¥/百万 token），侧边栏显示估算成本，并注明"未计入缓存命中折扣，实际可能更低"；
>
> **5. 纪律**：纯增量功能，不改 agent 行为与 prompt；usage 数据只用于展示，不进入对话上下文、不进 findings；配 pytest 用例（mock usage 验证提取与累计逻辑），完整套件跑通无回归。

## 你的验收点

1. 连续对话 3-4 轮，观察每轮"输入 token"是否逐轮上涨——**如果上涨，恭喜，你亲眼验证了上下文累积原理**；
2. 让 agent 做一轮带工具循环的任务（如"加载并分析"），确认本轮 token 包含了工具循环的消耗（比纯闲聊高）；
3. 侧边栏累计数 = 各轮之和，抽查一轮心算验证。

## 它未来的一个妙用（先记着，不做）

等你看一段时间 token 曲线后，可以加一个"上下文接近上限时提醒开新会话"的功能（input_tokens 超过阈值时侧边栏变黄/红）。那将是这个统计功能最有价值的下游应用——但现在先把数据跑起来，**先有仪表盘，再谈报警器**。

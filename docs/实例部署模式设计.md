## 1. 已确认输入（owner 提供，2026-09-07）

- 部署实例模型配置：`OPENAI_BASE_URL=http://127.0.0.1:8787/v1`、`DEFAULT_MODEL=hy3`
  （**只写部署机本地 `.env`，不进 git**——决策 4：key 仅 owner 持有）。
- 部署机即 owner 电脑：LLM 调用发生在部署机的 Python 进程内，因此
  `127.0.0.1:8787` 指**部署机本地**的模型代理/服务——同事浏览器**不需要**也
  不应该能访问该地址（常见误解，特此说明）。
- 数据通道结论（原则 3）：同事的数据必须先进部署机。方案 = 压缩包（zip）
  上传解压 + 单文件上传 + 部署机本地路径输入（owner 自用）。

## 2. "独立模块"的落地解释

主仓库新增**通用的实例模式能力**（代码进 git，不含任何 hy3/内网特化信息）；
实例的**全部特化内容只存在于部署机本地 `.env`**（base_url/key/model/
INSTANCE_MODE/口令）。开源用户克隆后默认就是阶段 A 形态，完全无感。若未来
部署资产膨胀再拆独立仓库，届时主仓库的实例模式代码原样复用。

## 5. 访问口令门（Commit B2）

- `ACCESS_PASSWORD` 非空即启用：任何访问者先输入口令，通过后
  `st.session_state["access_granted"]=True`（本会话有效，刷新需重输——
  Streamlit session 语义，可接受）；
- 比对用 `secrets.compare_digest`（防时序差）；判定逻辑抽纯函数可单测；
- 未配置（空串）= 不启用，行为与现状完全一致；
- 定位是**简单门禁**而非强鉴权：防的是局域网内"路过点开"，不防定向攻击
  （Streamlit 无 TLS，口令明文传输——文档注明，仅限可信内网使用）。

## 6. 压缩包数据通道（Commit B3）

- 数据面板新增"上传压缩包数据集（.zip）"：保存至 `outputs/uploads/` 后解压
  为目录，再走 `load_dataset_impl`（目录加载）；
- 解压安全四防线：
  1. 解压前从 zip central directory 校验**未压缩总大小**（默认上限 1GB）与
     **条目数**（默认上限 5000），超限拒绝（zip 炸弹防护，不落盘即拦截）；
  2. **zip slip 防护**：每个成员解析后的真实路径必须落在解压目标目录内
     （`resolve()` + `is_relative_to`），含绝对路径/`..` 穿越的成员直接拒绝；
  3. **中文文件名修复**：Windows 压缩的 zip 常无 UTF-8 标志（flag_bits
     0x800），zipfile 按 cp437 解出乱码——无该标志时按
     `filename.encode("cp437").decode("gbk")` 修复（国内真实痛点）；
  4. 解压目标为一次性新建时间戳目录，不与既有目录混写。
- 逻辑全部抽 `app/ui/upload_store.py` 纯函数（不 import streamlit），可单测。

## 9. 明确不做

- 不做 TLS/HTTPS（内网明文，文档注明边界）；
- 不做多用户/会话隔离（Streamlit 单进程多 session 共享 outputs/，内网可信
  场景可接受；文档注明）；
- 不做实时协作/排队（单机单进程，同事错峰使用）；
- hy3 特化逻辑不进代码（实例配置全走部署机 .env）。

### 终身回归：模型 API 异常不得炸穿界面（2026-09-10）

- **背景**：用户实测——模型服务返回 502（`CodeBuddy: upstream error (HTTP
  502)`），异常以裸 traceback 外抛、**炸穿 Streamlit 页面**（白屏 + 一大段
  堆栈，聊天记录还处于半截状态）。根因：`run_turn` 此前只兜
  `MaxTurnsExceeded`，模型侧故障（502/503/504/限流/超时/鉴权/网络）全部外抛，
  违反项目「错误可恢复 + 诚实降级」纪律。
- **回归用例**（改动 agent.run_turn 后重跑
  `tests/test_model_error_handling.py` 并做人工验收）：
  - **不崩**：模型抛任意 API 异常（含 502）→ UI 不白屏，聊天记录保留，
    用户看到可读提示（如"模型服务暂时不可用（502 上游错误）……请稍后重试"）；
  - **可重发**：异常分支返回的历史**必须含本轮用户消息**（否则用户"直接重发"
    时模型看不到上一句，回答脱节）——`MaxTurnsExceeded` 分支同款处理；
  - **分类话术**：502/503/504/429/401/404/网络/上下文超限各有对应提示
    （上下文超限指向侧栏「压缩历史」）；未知异常如实报类型+摘要（截断防灌爆），
    **不含 Traceback**；
  - **不吞中断**：KeyboardInterrupt / SystemExit 正常传播（用户主动中断）。
- **对话级**：模型故障后 agent 应如实说明"这不是数据或分析本身的问题"，并
  给出重试/检查配置的建议；不得假装成功、也不得只丢一段英文堆栈。

### 终身回归：批量纪律 + 单轮耗时可见（2026-09-10）

- **背景**：用户第二次实测 502——加载六目头戴式 MCAP（26 topic）后问"除变换
  外的 24 个数据流是否丢包"，再次返回 502。实测排除"单次请求过大"（单流同步
  检查返回仅约 236 token；即使逐流 24 次，最后一次 input 也仅约 7.8K token，
  远低于 262K 窗口）：真正诱因是**工具调用轮数**——若 agent 逐流发问，整轮
  串行十余次模型往返，累计耗时触及上游超时阈值。此前**没有任何事实可查**
  （不知道跑了几轮、耗时多少），只能靠猜，故本次同时做"减少轮数"与"让轮数
  可见"两件事。
- **架构侧收敛**（减少轮数）：
  - SYSTEM_PROMPT 第 14 条**批量纪律**：一次调用能覆盖 N 条流的绝不拆成 N 次，
    必须把范围一次性作为参数传给单个工具（`check_temporal_sync` 的 `streams`
    传文件名子串列表），只有返回被截断或确需按流换参数时才追加调用；
  - SYSTEM_PROMPT 第 15 条**耗时纪律**：先粗后细，不为了"更稳妥"重复调用
    已通过的流，不把一次调用能回答的问题拆成多轮追问；
  - 工具描述同步声明批量语义：`check_temporal_sync`（省略 streams 即全部流）、
    `check_sensor_sanity`（省略参数即全部传感器）、`align_container_streams`
    （本就是全量口径，**只调用一次**）。
- **观测增强**（让轮数可见）：
  - `run_turn` 回填 `RunMetrics`（duration_ms / n_model_calls / n_tool_calls /
    completed），**异常与 max_turns 分支同样回填**——失败轮的指标才是排查 502
    最需要的；`metrics` 参数缺省为 None 时行为与改动前完全一致（零回归）；
  - `ChatTurn.metrics` 透出到 UI：助手回复的「查看执行过程」面板首行显示
    "本轮耗时 X｜模型往返 N 次……"（未正常完成时明确标注）；侧栏 Token 统计
    追加会话级速度摘要（累计耗时 / 总往返次数 / **平均每次往返耗时**）。
- **回归用例**（重跑 `tests/test_run_metrics.py`、`tests/test_model_error_handling.py`、
  `tests/test_multi_session.py` 并做对话验收）：
  - **指标回填**：成功 / 异常 / max_turns 三分支都回填，且 `completed` 如实
    标 False；`KeyboardInterrupt` 仍正常传播；
  - **零回归**：不传 `metrics` 时 `run_turn` 返回契约不变；
  - **提示词纪律存在**：SYSTEM_PROMPT 含"批量纪律""耗时纪律"且点名 streams
    参数；三个批量工具的描述含"批量语义"字样；
  - **速度摘要口径**：平均每次往返耗时 = 累计耗时 / 总往返次数——该值低而
    总耗时高即"往返次数多"（可优化），该值本身高则属"单次慢"（方向不同）。
- **对话级**：问"多条流/全部流"的丢包、对齐、采样率问题时，agent 应**一次**
  工具调用覆盖全量并直接汇总；不得逐流调用再自行拼结论。若确实轮数偏高，
  用户可从「查看执行过程」的往返次数一眼看出，而不必再靠猜。

### 终身回归：路径入参规范化（引号/空白/不可见字符，2026-09-10）

- **背景**：用户实测**偶发**的侧栏加载失败——同一个 MCAP 文件，侧栏粘贴路径报
  "文件 X 不存在，请检查路径是否正确"，而在**对话里**让它加载同一路径却成功。
  根因是路径的两个入口规范不一致：侧栏 `st.text_input` 把粘贴内容原样透传
  （用户从对话记录/文档复制时很自然带上引号 `"C:\...\x.mcap"`，或尾随中文
  标点、零宽字符），引号成了路径的一部分，`Path.exists()` 返回 False，弹出
  误导性的"文件不存在"（文件完好无损）；而对话路径经模型抽取时引号已被剥离，
  所以永不中招。这也解释了"偶发"——只在用户粘了引号时才发生。
- **修复**：新增 `normalize_path_spec()`（幂等，只动首尾、不动路径本体），
  在 `load_dataset_impl`、`mcap_reader.probe_mcap`、统一读取入口
  `_readers.read_stream`（**在拆分子流之前**，仅作用于文件部分）三处接入。
- **回归用例**（重跑 `tests/test_path_normalization.py` 并做人工验收）：
  - **17 种污染形态**统一规范化为同一裸路径：ASCII 双/单/反引号、中文左右
    双/单引号、直角引号、全角引号、嵌套混合包裹（`“"path"”`）、前后空格、
    尾部换行、零宽空格、BOM、尾随全角逗号/中文句号、正斜杠、`file://` URL；
  - **幂等**：反复规范化结果不变；
  - **零误伤**：路径**中间**的引号（`a'b.csv`）与空格（`My Documents`）保留，
    UNC（`\\server\...`）与 Unix 路径（`/home/...`）不被改写——分隔符统一只在
    盘符形态（`C:/...`）下生效；
  - **端到端**：带引号路径加载**成功**且返回 `path_normalized`（原值/实用值）
    并在 user_message 诚实告知"已自动剥离"；干净路径不产生该提示（防噪声）；
  - **诚实报错**：剥离后仍不存在时，提示必须含"已自动剥离"并给出实用路径，
    不得只让用户"检查路径"（引号肉眼难辨，否则无法自查）；
  - **子流路径**：`"<file>::<sub>"` 只规范化文件部分，子流名保持原值
    （h5 节点 / mcap topic 是登记表原值，可能含任意字符）。
- **对话级**：用户粘贴带引号路径报警时，agent 应说明"引号已被自动剥离"而非
  复述"文件不存在"；侧栏与对话两个入口对同一路径的行为必须一致。

### 终身回归：产物按数据集子目录归类（2026-09-11）

- **背景**：产物此前平铺在 `outputs/` 根目录，19 张 png + 11 个 md 混杂、超长
  文件名（dataset_id 可达 50+ 字符）难以查找与清理；确认画像也集中在单个
  `outputs/.dataset_profile.json`（多数据集共用一个文件，靠全局锁保护）。
- **回归用例**（重跑 `tests/test_output_paths.py`、`tests/test_profile_store.py`、
  `tests/test_multi_session.py` 并做人工验收）：
  - **子目录归类**：图表落 `by_dataset/<净名>/charts/`、报告落
    `.../reports/`、画像落 `.../profile.json`；未加载数据集时落 `_misc/`；
  - **文件名规则不变**：仍含 `session_tag` 前缀与 dataset_id（多会话隔离契约
    零回退）；
  - **净名不碰撞**：两个前 60 字符相同、尾部分不同的超长 dataset_id 映射到
    **不同**目录（无条件追加短哈希）；危险字符被替换；空名兜底 `_misc`；
  - **画像迁移**：旧全局 `.dataset_profile.json` 中该数据集的分片可被读取并
    迁移到新路径；旧文件保留不删；**新路径优先**于旧文件（旧数据不覆盖新确认）；
  - **并发不回退**：两会话同时确认同一数据集的不同流 → 两条都在；无残留
    临时文件与锁文件。
- **对话级**：引用 `user_confirmed` 标签时说明"持久化确认画像（跨会话生效）"
  即可，不得硬编码旧路径 `outputs/.dataset_profile.json`（新位置为
  `outputs/by_dataset/<数据集名>/profile.json`）。

    parse_failed），user_message 含可执行修复指令（`pip install tables`）
    与澄清句"并非文件损坏"，**不含"可能……已损坏"类误导兜底**；
  - **依赖清单**：requirements.txt 含 tables（.h5 宣称支持则依赖齐全）；

  读取"，不得附和"文件可能损坏"的猜测，并给出安装指令。

### 终身回归：h5py 原生层级结构（非 pandas HDFStore）可加载

- **背景**：用户实测——具身智能采集的 dataset.h5（46.8MB，action/observation/
  pose/meta 层级，compound dtype 结构化数组 + 标定矩阵）加载报"未找到可读取
  的 DataFrame 表"。根因：`_load_hdf5` 只支持 pandas HDFStore 格式
  （PyTables 打开 → read_hdf），而该文件是 h5py 直接写的原生层级——PyTables
  能打开、keys 非空但 read_hdf 全败。且缺依赖修复后错误分类已正确切换
  （missing_dependency → "未找到 DataFrame 表"），证明文件被真实读取。
- **回归用例**（改动 _load_hdf5/_load_hdf5_native 后重跑
  `tests/test_h5_native.py`、`tests/test_h5_dependency.py`）：
  - **h5py 层级可加载**：compound dtype 节点转 DataFrame（字段名即列名，
    子数组字段保持 object 列）；主表为信息量最大节点（行数×列数，并列按
    路径字母序）；返回带 `h5_source_node` 与 `h5_structure`（全部候选节点
    清单，截断 20）；user_message 说明层级结构与主表节点。
  - **既有格式不回退**：pandas HDFStore 格式仍走 read_hdf 路径；非 HDF5
    文件仍 parse_failed（"可能损坏"措辞此时恰当）。
- **期望行为**：具身智能常见的 h5py 层级采集文件开箱可读；文件内多个数据
  节点全部可见（用户知道还有什么表）；不把格式不兼容误报为文件损坏。

### 回归用例：消息编辑重发（2026-09-09）

- **背景**：用户需求——像网页 ChatBot 一样编辑已发消息并让 bot 重新回答。
  语义核心不只是改 UI：被编辑消息**之后**的一切轮次必须从 agent 历史中
  同步移除，否则 bot 会"记得"已被编辑掉的旧内容，重新回答不干净。
- **回归用例**（改动 streamlit_app 对话区 / chat_service 后重跑
  `tests/test_chat_edit.py`、`tests/test_streamlit_app.py` 并做人工验收）：
  - **结构**：仅最近一条用户消息显示 ✏️ 编辑入口（历史深处不显示，避免
    大面积重生成，与主流对话 UI 一致）；编辑态为预填原文的文本框 +
    "保存并重新生成 / 取消"；
  - **截断语义**：保存后 agent 历史截断到该轮之前——旧回答、旧工具返回
    （含大 JSON）不残留（`truncate_history_to_turn` 单测覆盖）；
  - **重生成**：bot 基于编辑后的文本重新回答，token 累计照常记入。
- **人工验收**：编辑中间消息后再提问与旧对话相关的问题，bot 的回答不得
  引用被编辑掉的旧内容。

### 终身回归：h5 节点流接入全工具链（sync/propose/inspect 采样率）

  - **inspect 采样率**：h5 节点 timestamp 字段实测，单位 ms 正确（不再

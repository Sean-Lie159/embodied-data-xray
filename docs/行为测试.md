### 终身回归：自然语言确认请求自动翻译 + tf 验证器展开列模式

- **背景**：用户实测两处缺陷——①开发者给用户的对话指令含工具名/参数
  （propose_stream_semantics / kind / time_column），普通用户无从下手；
  agent 对用户自然语言的类别表达（"这些是触觉"）未自动翻译为 propose 流程。
  ②tf.jsonl 确认验证 failed（"未发现 transforms 类列表结构"）——根因是
  展开视图把 list[dict] 消化为扁平列（data.transforms.0.parent_frame_id），
  验证器找原始 list 永远落空，tf 流永远无法通过验证（hard bug）。
- **回归用例**（改动 propose_semantics / inspect_streams / SYSTEM_PROMPT 后
  重跑 `tests/test_tf_verification.py`、`tests/test_inspect_guidance.py`）：
  - **tf 验证 strong**：真实 tf 结构（data.transforms[0] 含
    parent_frame_id/child_frame_id）经展开列名特征验证 strong；
    confirm=True 落盘后重载生效（完整闭环）。
  - **hint 边界**：恰半数流确认时 hint 仍触发（旧实现 `<0.5` 在 13/26 场景
    漏报——真实事故）；hint 要求流数 ≥5 防小数据集噪声（设计保留）。
  - **对话级**：用户用自然语言表达类别/命名（"这些是触觉""帮我把这些流
    归类"）时，agent 自动翻译为 propose 流程——自行推断 kind/标签/
    time_column/结构证据，**不要求用户提供字段路径等内部细节**；对用户的
    表述用功能语言（"我把这些流归类为触觉并记住了"），不展示工具名与参数。

### 终身回归：缺依赖 ≠ 文件损坏（user_message 诚实性）

- **背景**：用户实测——h5 加载报 "Missing optional dependency 'pytables'"，
  但 user_message 兜底措辞为"可能不是有效的 h5 数据，或文件已损坏"——文件
  根本没被读过（缺依赖在打开文件之前就失败），"可能损坏"是误导性兜底。
  另 requirements.txt 只装了 h5py（另一个 HDF5 库），没装 pandas 读 HDF5
  实际需要的 tables——.h5 是宣称支持格式，依赖清单漏项。
- **回归用例**（改动 load_dataset 的 MissingDependencyError 分支后重跑
  `tests/test_h5_dependency.py`）：
  - **结构化区分**：缺依赖 → `error="missing_dependency"`（独立于
    parse_failed），user_message 含可执行修复指令（`pip install tables`）
    与澄清句"并非文件损坏"，**不含"可能……已损坏"类误导兜底**；
  - **依赖清单**：requirements.txt 含 tables（.h5 宣称支持则依赖齐全）；
  - **对照**：装齐依赖后真坏的 h5 → parse_failed（此时"可能损坏"措辞恰当）。
- **对话级**：agent 转达缺依赖错误时，应如实说明"是环境缺件、文件未被
  读取"，不得附和"文件可能损坏"的猜测，并给出安装指令。

### 终身回归：h5py 原生层级结构（非 pandas HDFStore）可加载

- **背景**：用户实测——具身智能采集的 dataset.h5（46.8MB，action/observation/
  pose/meta 层级，compound dtype 结构化数组 + 标定矩阵）加载报"未找到可读取
  的 DataFrame 表"。根因：`_load_hdf5` 只支持 pandas HDFStore 格式
  （PyTables 打开 → read_hdf），而该文件是 h5py 直接写的原生层级——PyTables
  能打开、keys 非空但 read_hdf 全败。且缺依赖修复后错误分类已正确切换
  （missing_dependency → "未找到 DataFrame 表"），证明文件被真实读取。
- **回归用例**（改动 _load_hdf5/_load_hdf5_native 后重跑
  `tests/test_h5_native.py`、`tests/test_h5_dependency.py`）：
  - **h5py 层级可加载**：compound dtype 节点转 DataFrame（字段名即列名，
    子数组字段保持 object 列）；主表为信息量最大节点（行数×列数，并列按
    路径字母序）；返回带 `h5_source_node` 与 `h5_structure`（全部候选节点
    清单，截断 20）；user_message 说明层级结构与主表节点。
  - **既有格式不回退**：pandas HDFStore 格式仍走 read_hdf 路径；非 HDF5
    文件仍 parse_failed（"可能损坏"措辞此时恰当）。
- **期望行为**：具身智能常见的 h5py 层级采集文件开箱可读；文件内多个数据
  节点全部可见（用户知道还有什么表）；不把格式不兼容误报为文件损坏。

## 元规则：接入新真实数据格式时，先提取结构骨架"

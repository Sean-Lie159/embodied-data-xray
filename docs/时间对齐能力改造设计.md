# 时间对齐能力改造设计说明（2026-09-04 草案，待确认）

> 本文遵循 AGENTS.md 第 4 条"先文档后代码"，动工前需经 owner 确认。
> 诊断过程与证据见 `research_report_harness_optimization.md`。

---

## 1. 背景与动机

2026-09 在真实数据集 `wujiGlove_data`（wuji 自研 ego 双手数据手套，MCAP 导出的
26 个 jsonl 流）上做时间对齐分析，最后一轮用户要求"做左右手套低频流逐帧对齐
（最近邻残差）"，Agent 无法完成，连续三轮只能解释工具限制。

排查后确认：**这不是一个"缺参数"的问题，而是四个独立缺陷叠加，参数问题排第四**。
前两个缺陷使工具输出了系统性失真的数值——`duration≈5.28e10`、`actual_rate_hz=0.0`、
`frame_loss_ratio≈0.9986`、`残差 2.43e11 ms`——而 Agent 基于这些失真值产出了一篇
看似合理、实则数值全错的报告。这比"做不了"更危险。

故本次改造的优先级是：**先让工具输出可信的数，再让工具可被精确指挥**。

---

## 2. 设计目标

1. **数值可信**：时间戳单位必须被正确识别；识别不出时明确标注不可用，不产出
   看似合理的伪值。
2. **基线合理**：对齐基线排除静态/标定/元数据类流，并给出可转述的推荐理由。
3. **可被精确指挥**：支持指定基线流、流子集、时间列，支持定位数据缺口。
4. **字段名自带单位**：杜绝模型被 `_s` 后缀误导（本次事故的直接放大器）。
5. 保持单 Agent + 工具循环，不新增 Agent；保持质检层统一返回契约。

---

## 3. 根因分析（四个缺陷）

### 缺陷 1：时间戳单位链路断裂（P0，事故主因）

链路断在"两套时间戳识别逻辑能力不对称"。

`_sniffing.py` 的 `find_timestamp_columns`（`_sniffing.py:129`）有完整两级机制：
词表命中优先，**未命中走内容指纹回退**，能正确把 `mcap_log_time_ns` 判为 `ns`。
但真正写进流登记表 `timestamp_unit` 的是 `fingerprint_timestamp`（`_sniffing.py:500`），
它**只查白名单、无回退**：

```python
_TIMESTAMP_COLS = ("timestamp", "timestamp_ns", "time", "ts", "ts_ns", "t", "stamp",
                   "frame_time", "pts", "pts_us", "frame_timestamps_ns", ...)
```

`mcap_log_time_ns` 不在该元组 → `present=False` → `timestamp_unit="unknown"`。
`check_temporal_sync.py:436` 仅在单位是已知时间单位时才自我纠正，unknown 被排除；
随后 `_normalize_to_ns` 的 unknown 兜底把纳秒原值当秒乘 1e9，且返回
`normalized=True`，导致 `_to_seconds` 再除 1e9——一来一回数值回到原始纳秒，
**但字段名是 `duration_s` / `median_interval_s`**。模型看到 `5.28e10` 配 `_s`
后缀，只能得出"528 亿秒"。

此兜底违反 `timestamp_units.py` 自述契约"无法推断时标 unknown，**绝不硬猜**"，
也违反 `docs/技术债.md` 第 3 条"单位换算必须由工具确定性完成，不适用 LLM 假设
通道"——因此**不能靠 prompt 补，只能改代码**。

附带发现：`inspect_streams._measure_rate_from_file`（`inspect_streams.py:137`）对
unknown 用的是**另一套兜底**（`1.0 / mean_interval`，按秒算 Hz），与
`check_temporal_sync` 的兜底结果不一致。同一份数据、同一 unknown 单位，两个工具
给出两个不同的错误答案（1.2e-7 Hz vs 0.0 Hz）。必须统一。

### 缺陷 2：基线策略把静态流推上基线（P0）

`check_temporal_sync.py:520` 选"帧率最低的流"当基线，把 105 个点的
`tf_static.jsonl` 选了上来。`tf_static` 是 ROS 静态坐标变换广播，本就不随时间变化，
是全场最不该参与时间同步判定的流。

**此缺陷与缺陷 1 独立**：单位修好后 tf_static 的 2 Hz 仍是全场最低，照样被选中。
按 ARCHITECTURE.md 3.3.1 已确立的"语义角色优先"原则，静态/标定/元数据类流应像
`detect_episode_mirrors` 处理镜像文件那样被显式排除。

### 缺陷 3：流的时间形态未分类（P1）

现丢帧口径（`check_temporal_sync.py:196`，异常间隔累加法）对周期型流正确，
对突发型流系统性误报：IMU/tf 突发内间隔仅 1–2 µs，突发间毫秒级静默全部超过
5×中位间隔 → `frame_loss_ratio≈0.9986`。

对话中 Agent 推断"IMU 与 tf 是突发密集型流，796 Hz 不是真丢帧"——判断正确，
**但这是模型猜的，工具并未输出该信息**。工具缺形态分类（periodic / burst / static）。

### 缺陷 4：接口无参数，且 docstring 主动劝退（P1）

注册给 Agent 的 8 个工具中仅 `check_temporal_sync` 与 `inspect_streams` 无参。
`check_temporal_sync` 的 docstring 明写 `Args: 无（基于 RunContext.meta）`，
等于告诉模型"你控制不了我"，模型连试都不试即进入"如实说明限制"模式。

项目已有带参过滤流的成熟先例（`check_sensor_sanity(sensor, table)`、
`plot_chart` 6 参数），加参数不引入新模式。

## 4. 改造设计

### 4.1 单位链路统一（P0，先做，不动接口）

**4.1.1 消除两套识别逻辑的能力不对称**

`fingerprint_timestamp` 不再自己用白名单过滤，改为复用 `find_timestamp_columns`
（它已有指纹回退），消除"登记表用弱逻辑、`_read_timestamp_only` 用强逻辑"的分裂。

**4.1.2 unknown 不再被无条件采信**

`check_temporal_sync` 读取时间戳后，用 `_read_timestamp_only` 返回的列名
（Series 的 `name`，即 `mcap_log_time_ns`）重跑 `infer_unit` 做交叉校验；
登记表里的 unknown 只允许在该交叉校验同样失败时才成立。

同时把 `self_correct_unit` 的覆盖范围从"已知时间单位"扩展到 unknown：
unknown 时以量级重推断（`infer_unit(arr)`）为起点尝试纠正。**纠正成功的判据仍是
"采样率落在物理合理区间"**（`MIN_PLAUSIBLE_RATE`~`MAX_PLAUSIBLE_RATE`），这是
项目已有机制，不引入新启发式。

**4.1.3 unknown 兜底改为"显式不可用"**

`_normalize_to_ns` 对 unknown 由 `ts * 1e9, normalized=True` 改为
`ts, normalized=False` + `basis="单位未知，未归一化，该流不参与跨流对齐"`。
下游 `_to_seconds` 不再做那次致命除法。

代价：单位真未知的流不参与对齐。这是**正确**的取舍——与其给出一个错到离谱的
残差，不如明确说"这条流无法参与对齐"。

**4.1.4 统一 inspect_streams 的兜底**

`_measure_rate_from_file` 改用与 4.1.3 相同的判定，unknown 时返回
`present=True, sample_rate_hz=None, unit_note="单位未知，未计算采样率"`，
不再产出 1.2e-7 Hz 这类伪值。

### 4.2 基线策略：先排除，再推荐（P0）

**排除集**（任一命中即不作为基线候选，但仍做单流检查）：
- 形态为 `static`（见 4.5）或帧数过少（< 100）；
- 语义角色为标定 / 元数据 / 镜像（复用既有 `is_calibration_file`、
  `_is_dataset_metadata_file`、`detect_episode_mirrors`）；
- `frame_indexed`（帧序号流，无物理时间）——现有逻辑已排除，保持；
- 文件名/路径含 `tf_static`、`static`、`calib`、`metadata`。

> 术语说明：`tf_static` 是 ROS 的"静态坐标变换"，记录传感器之间固定的安装关系，
> 发布一次即可，不随时间变化。通俗讲，它是"装配图纸"而不是"录像"。

**推荐打分**（剩余候选中取最高分）：

```
score = coverage_ratio × stability × log10(n_samples)
  coverage_ratio = 该流时间跨度 / 全部候选流的最大时间跨度   （覆盖完整性）
  stability      = 1 / (1 + 差分变异系数)                    （间隔稳定性）
```

即"覆盖整段录制、间隔稳定、点数足够"的周期型流优先。返回中附：

```python
"baseline_recommendation": {
    "stream": "…/left_glove_emf_poses.jsonl",
    "reason": "覆盖全时长（100%）、间隔稳定（变异系数 0.02）、帧数 6339，为周期型流",
    "score": 0.98,
    "excluded": [{"stream": "…/tf_static.jsonl", "reason": "静态流（不随时间变化），不作为基线"}],
}
```

模型可直接转述 reason，不必自行解释。

### 4.3 接口参数化（P1）

```python
@tool
def check_temporal_sync(
    wrapper: RunContextWrapper[RunContext],
    baseline_stream: str | None = None,
    streams: list[str] | None = None,
    time_column: str | None = None,
    locate_gaps: bool = False,
) -> dict:
    """检查各流之间的时间同步与漂移（v1，仅时间戳一致性）。

    逐流读取时间戳，检查单调性、重复、丢帧、采样率、时长，并做流间最近邻对齐
    残差与窗口漂移检测。默认自动推荐基线并对全部可对齐流检查；可用参数收窄范围。

    Args:
        baseline_stream: 可选，指定对齐基线流（路径或文件名的子串，如
            "left_glove_emf_poses"）。省略时自动推荐（排除静态/标定/元数据流，
            按"覆盖全时长 + 间隔稳定 + 帧数充足"打分）。指定值无法匹配任何流时
            返回结构化错误并列出可用候选，不静默回退。
        streams: 可选，只检查这些流（子串列表，如 ["left_glove", "right_glove"]
            表示只比对左右手套）。省略时检查全部可对齐流。
        time_column: 可选，指定用哪一列作为时间戳（列名或子串）。数据集含多个
            时间列（如 MCAP 的 log_time 与 publish_time）时用它明确指定；
            省略时按"物理时间优先、log_time 优先于 publish_time"自动选择。
        locate_gaps: 默认 False。置 True 时额外返回每个数据缺口的起止时刻、
            持续时长与估算缺失帧数（条数受 sync_gap_report_limit 限制）。

    Returns:
        统一质检返回格式。measurements 内含 stream_checks（逐流指标，字段名带
        单位后缀）、residuals（相对基线的最近邻残差，含带符号中位数）、
        drift（漂移斜率）。单位未知的流在 streams_status 中标注未参与及原因。
    """
```

**关键：docstring 必须从"Args: 无"改写为上述形式。** 这是让模型敢于用参数的前提——
模型只看得到工具 schema，看不到实现。

**参数设计说明**：
- `streams` 用子串匹配，配合"左右手套""低频流"这类自然表达，避免模型必须背出完整路径。
- `baseline_stream` 匹配失败时**返回结构化错误 + 候选清单**，绝不静默回退到自动基线
  （静默回退会让模型误以为指定生效）。
- 待验证：`list[str]` 参数在 openai-agents 的 schema 生成中是否正常。若有问题，
  退回逗号分隔字符串并在 docstring 中写明。

### 4.4 数据缺口定位（P1）

`locate_gaps=True` 时，对每条流输出：

```python
"gaps": [
    {"start_ns": 1787294458000000000, "end_ns": 1787294460000000000,
     "duration_ns": 2000000000, "missing_frames_est": 207,
     "position_in_recording": "0.42–0.46（相对整段录制的归一化位置）"}
]
```

条数上限由 `sync_gap_report_limit` 控制（默认 20），超出时返回前 N 条并注明总数，
避免污染上下文（AGENTS.md 第 5 条上下文节俭）。

这直接回答本次真实需求："右手那 207 帧缺口落在哪里"。

### 4.5 流形态分类（P1）

在单流检查中输出 `stream_shape`：`periodic` / `burst` / `static`。

**判据**（基于差分分布，确定性，不引入新启发式；2026-09-04 实现时修正）：

> 实现修正说明：原草案的 burst 判据（"间隔 < 中位间隔/10 的占比 ≥ 阈值"）在
> 突发序列上失效——突发流的中位差分本身落在突发内的小间隔侧，该占比趋近 0。
> 改用等价且更稳健的比值判据：平均间隔被突发间静默拉高而中位数不变。

```
burst：平均间隔 ≥ 中位间隔 × sync_burst_interval_ratio（默认 3.0）
        （真实数据：IMU 均值 1.26ms / 中位 1.79µs ≈ 700）
static：帧数 < sync_static_min_samples（100）或 中位间隔 > 流自身跨度 / 10
其余   →  periodic
```

**burst 流的指标改报**（`frame_loss_ratio` 置 None 并标注不适用）：

```python
{"stream_shape": "burst",
 "n_bursts": 16603,
 "intra_burst_median_interval_ns": 1792,
 "effective_rate_hz": 796.0,          # 样本数 / 时长，唯一对突发流有意义的速率
 "frame_loss_ratio": None,
 "frame_loss_status": "not_applicable",
 "burst_note": "突发型流：丢帧率口径不适用，改用有效速率与突发次数刻画"}
```

**实现补充**（Commit D 落地时确定）：
- burst 流不参与漂移检测——跨突发的最近邻偏移是纯噪声（突发间静默的相位差），
  线性回归会误报漂移；drift detail 中标注"不参与"及原因。
- 带符号残差约定：`目标流时间戳 − 基线最近邻`，正值 = 目标流比基线晚；
  真实手套流间固定偏移为亚毫秒级，在最近邻可测范围（< 半采样间隔）内，
  超过半采样间隔的固定时延会发生相位折叠，须由互相关物理对齐（v2）实测。
- burst 流的 locate_gaps 同样不适用（每个突发间静默都会被判为缺口），
  输出 note 说明。

> 通俗解释：突发型流像"连拍"——一次拍几十张、间隔极短，然后停顿。用"平均多久
> 拍一张"去衡量它，会把每次停顿都算成"丢帧"。对这类流只该问"平均每秒拍到几张"
> （有效速率）和"连拍了多少段"。

**顺带增强**：`_align_residuals` 与 `_detect_drift` 现为 Python 逐点循环
（82619 点 × 27 流），改为向量化 `np.searchsorted`。残差增加**带符号中位数**——
它是"目标流相对基线流的固定时延"的估计量；现有 mean/max/p95 全为绝对值，
回答不了"A 比 B 晚多少"。

### 4.6 返回字段单位规范（贯穿全部改动）

**所有时长/间隔字段改用显式单位后缀**：

| 现字段名 | 新字段名 | 说明 |
|---|---|---|
| `duration_s` | `duration_ns` | 录制时长（纳秒） |
| `median_interval_s` | `median_interval_ns` | 中位间隔（纳秒） |
| `residual_mean_ms` | `residual_mean_ms` | 保持，本就是毫秒且正确 |

写回 `meta["qc"]` 的字段同步改名。`generate_report.py:132` 引用了
`frame_loss_ratio` / `actual_rate_hz`（这两个名字符合规范，不动），
`:136` 引用 `residual_max_ms` / `residual_mean_ms`（不动）——需确认无其他处
引用 `duration_s` / `median_interval_s`（实施前用 grep 复核）。

另在返回顶层增加：

```python
"unit_warnings": [
    "流 X：时间戳单位未知，未归一化，不参与跨流对齐（列名 mcap_log_time_ns 未命中词表）"
]
```

让"哪些指标不可用"成为显式字段，而不是让模型从 basis 文本里猜。

5. **不改 SYSTEM_PROMPT 之外的 Agent 结构**，不引入多 Agent / handoff。

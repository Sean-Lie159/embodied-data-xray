# 四层语义识别架构设计说明（2026-08-24）

## 1. 背景与动机

现有语义识别（`app/tools/_sniffing.py`）是"词典先验"的单一机制：`sniff_table_columns`
用子串匹配列名（如含 "accel"/"gyro" → IMU），`infer_role` 用触发词映射角色。在真实数据
`20260821_144044` 上暴露多重缺陷：

- `camera_params_*.json` 被 `infer_role` 判为 "RGB 相机"（实为标定文件）；
- `hand_tracking.csv` 的 `left_joint*`/`right_joint*` 列无合理语义，且可能被误标；
- 无力传感器数据却可能被误报 "力/力矩 ✓"；
- `accel.csv` 与 `gyro.csv` 未被配对为六轴 IMU；
- `controller_poses.csv`（1KB）被当作正常位姿流，实为空流；
- `<name>.mp4` 与 `<name>_metainfo.csv` 未配对，导致视频流无法用 metainfo 表
  的时间戳参与时间戳级对齐，`check_temporal_sync` 在真实数据上跑不通。

## 2. 设计目标

把"识别类型"从"词典猜一个答案"升级为"多层证据裁判"，且每一层判定都带**依据说明**、
可回溯、可被用户纠正并持久化。识别结果不再"一刀切死刑"，而是"证据不足则降级待定"。

## 3. 四层架构总览

语义识别分四层，按优先级从低到高、证据从强到弱（高优先级层覆盖低优先级层的结论）：

```
第 4 层  用户确认 + 持久化  →  .dataset_profile.json（最高优先，下次加载先读）
第 3 层  LLM 语义假设 + 工具验证 → verify_semantic_hypothesis 工具
第 2 层  内容指纹裁判（确定性）  → 时间戳/四元数/标定矩阵等数值指纹
第 1 层  词典先验（仅线索）     → 现有词典降级为"线索"，未命中不得判死刑
```

### 3.1 第 1 层：词典先验（降级为线索）

现有 `sniff_table_columns` / `infer_role` 的词典匹配**不删除**，但语义从"判定"降级为
"线索候选"：词典命中只产生一条 `candidate`（含来源 = 词典、命中词、置信度），**未命中
不得判死刑**（不再有"无命中即 unknown 且结束"的绝对语义）。词典结果需第 2 层指纹
验证后才可升级为"成立"。

### 3.2 第 2 层：内容指纹裁判（确定性，核心新增）

对每条表格流读取**少量样本数据**（nrows 采样，如 500 行）做确定性数值指纹判定，
判定必须附"依据说明"（基于哪些列、测得什么数值、得到什么结论）。指纹规则：

- **时间戳指纹**：存在时间戳列（`timestamp*`/`ts*`/`exposure_start_utc_ns` 等）且
  数值列单调递增、差分大致均匀（中位数间隔下，差分 < 阈值比例的占比高）→ 该列为
  时间戳。依据说明含"列 X 单调递增、间隔中位数 Y"。
- **四元数指纹**：四列成组且每行模长 ≈ 1（如 `quat_x/y/z/w`、`*_orientation_x/y/z/w`）→
  判定为四元数组。依据说明含"列 Q 每行模长 ≈ 1（最大偏差 < 0.01）"。
- **标定 JSON 指纹**：JSON 含小尺寸数值矩阵特征——内参 `intrinsics`（如 focalX/
  centerX/radialDistortion）、畸变系数、外参四元数（`extrinsics.rotation` 四元数）、
  `bias`/`scale`/`noise`（IMU 标定）等 → 判为标定文件。依据说明含"含 intrinsics/
  extrinsics/rotation/bias 等标定键"。
- **力/力矩指纹**：需同时满足"列名含 force/torque/ft/fx/fy/fz/tx/ty/tz" **且** 数值在
  力/力矩量纲合理范围。无力传感器数据（如纯位姿流）不得误报 force。

### 3.3 第 3 层：LLM 语义假设 + 内容指纹验证（内部函数，不注册新工具）

第 3 层**不新增 agent 工具**（保持单 Agent + 工具循环结构）。内容指纹验证逻辑实现为
`_sniffing` 内部函数，在 `load_dataset` 嗅探流程中自动执行：对每条表格流读取少量样本
（如前 500 行），调用第 2 层指纹函数做确定性验证，结果写入流注册表的
`semantic_label` / `label_evidence` / `label_confidence` 字段。

LLM 的"语义假设"来自其自身对话理解（基于 `inspect_streams` 返回的标签与证据），
"验证"由确定性指纹函数把关——LLM 读到证据即可解释"为何这个流被标成 IMU"，信息不丢失，
只是走更便宜的通道（读 `inspect_streams` 而非新工具）。这样既不破坏单 Agent 约束，
又让 agent 的语义推断受数值证据约束。

### 3.4 第 4 层：用户确认 + 持久化（自然语言入口，outputs/ 下）

用户对某条标签提出质疑时，agent 用**自然语言对话**处理（沿用现有单 Agent 循环，不新增
工具），确认结果通过内部函数写入项目 `outputs/` 目录下的 `.dataset_profile.json`
（集中管理，**不进数据集目录**，避免污染原始数据）。再次加载该数据集时，`load_dataset`
优先读取此文件（最高优先，覆盖第 1-3 层）。文件内每个映射标注来源：
`user_confirmed` / `content_fingerprint` / `dictionary`。

`.dataset_profile.json` 结构示意（落在项目 `outputs/` 下，按数据集目录名索引）：
```json
{
  "schema_version": 1,
  "dataset_id": "20260821_144044",
  "streams": {
    "accel.csv": {"kind": "imu", "role": "IMU 加速度", "source": "content_fingerprint",
                  "evidence": "列 timestamp_ns 单调递增，间隔约 1016Hz"},
    "gyro.csv": {"kind": "imu", "role": "IMU 角速度", "source": "content_fingerprint"}
  },
  "pairs": [
    {"type": "video_metainfo", "video": "rgb.mp4", "metainfo": "rgb_metainfo.csv",
     "source": "content_fingerprint"},
    {"type": "imu_6axis", "streams": ["accel.csv", "gyro.csv"], "source": "content_fingerprint"}
  ],
  "user_confirmed": {
    "hand_tracking.csv": {"kind": "hand_tracking", "role": "手部跟踪", "source": "user_confirmed"}
  }
}
```

## 4. 流配对规则

### 4.1 视频 ↔ metainfo 配对

规则：`<name>.mp4` ↔ `<name>_metainfo.csv`（同名 + 前缀 `_metainfo`）。配对的 metainfo
表登记为该媒体流的时间戳来源。`check_temporal_sync` 前置条件更新：视频流存在配对
metainfo 表时，可经该表参与时间戳级对齐（读取 `exposure_start_utc_ns`/`pts_us` 等），
`verification_level` 仍为 `timestamp_consistency`，但注明"时间戳来自曝光元数据而非
容器"。

真实样本配对：`rgb.mp4↔rgb_metainfo.csv`、`ctrl.mp4↔ctrl_metainfo.csv`、
`tracking.mp4↔tracking_metainfo.csv`、`audio.m4a↔audio_metainfo.csv`。

### 4.2 accel + gyro → 六轴 IMU

规则：目录内存在 `accel*.csv` 与 `gyro*.csv` 且时间戳列一致/可比 → 配对为一组六轴
IMU（`imu_axes=6`）。`inspect_streams` 的 IMU 汇总把二者作为同一组 IMU 的多个子流输出。

## 5. 空流检测

行数 ≤ 2 的表标记为"未使用/空流"，流清单显式标注（`status: "empty"`），**不计入可对齐
流数**。真实样本：`controller_poses.csv` 仅 1KB（可能仅表头或 1-2 行）→ 标记空流，不再
当作正常位姿流参与对齐。

## 6. 修正已知误判

- `camera_params*.json` 识别为**标定**（依据：含 intrinsics/extrinsics/rotation 标定
  指纹），不得被 `infer_role` 判为 "RGB 相机"。文件名含 `camera_params` 时按标定优先。
- `hand_tracking*.csv` 不得标为 IMU。其列含 `joint*_orientation_*`（四元数）、
  `*_active`、`*_joint*_id/name`，应识别为"手部跟踪/关节数据"（kind=hand_tracking），
  而非 IMU 或位姿流。
- **无力传感器数据不得标"力/力矩 ✓"**：force 判定需第 2 层数值指纹佐证，不能仅凭
  列名子串（如 `fx`/`fy`/`fz` 在相机位姿流里可能指某坐标分量）。

## 7. 改动范围与 commit 拆分

本设计确认会**大改 `_sniffing.py` 存量代码**（`sniff_table_columns`、`infer_role`、
`is_calibration_file`、`build_capabilities`、`build_streams_registry` 全被触及），并
跨模块联动：`load_dataset.py`、`inspect_streams.py`、`check_temporal_sync.py`、新工具
`verify_semantic_hypothesis`、持久化 `.dataset_profile.json`、`docs/行为测试.md`、新增
pytest。

为避免一个超大改动难以回滚/评审，**拆为两个独立 commit**：

**Commit A — 语义识别内核（纯逻辑，不动工具接口）**
- 第 1 层词典降级 + 第 2 层内容指纹裁判（时间戳/四元数/标定/力指纹，含依据说明）；
- 流配对规则（mp4↔metainfo、accel+gyro）；
- 空流检测 + 修正已知误判（camera_params/hand_tracking/力）；
- 在 `_sniffing.py` 内重构嗅探产出（每流带 kind/role/evidence/status）；
- 新增 pytest（真实命名构造：pts_us、exposure_start_utc_ns、camera_params_rgb.json、
  imu_calibration.json、hand_tracking 26 关节列、accel+gyro 配对、metainfo 配对、
  中文文件名"信息.jpg"）；
- 更新 `check_temporal_sync` 前置条件（视频配对 metainfo 参与对齐）。

**Commit B — 用户持久化层（新增能力层）**
- 第 3 层验证函数已随 Commit A 入库（内部函数 + 流注册表字段）；
- 第 4 层用户确认：自然语言对话入口，确认结果经内部函数写入 `outputs/` 下
  `.dataset_profile.json`；
- `load_dataset` 加载时优先读取该文件（覆盖第 1-3 层）；
- 关联 pytest 与行为测试用例。

Commit A 自含完整可测的语义识别内核；Commit B 在其上叠加 LLM 假设与持久化，
两层边界清晰，便于分别评审与回滚。

## 8. 验收锚点（真实目录 `20260821_144044`）

- 4 个标定文件（`camera_params_ctrl/rgb/tracking.json`、`imu_calibration.json`）识别为
  标定；
- 力/力矩不再误报（`head_pose.csv`、`hand_tracking.csv` 等无 force 证据的流不报）；
- `accel.csv` + `gyro.csv` 配对为六轴 IMU；
- `controller_poses.csv`（1KB）标记为空流，不计入可对齐流数；
- 三个 metainfo 与对应 mp4 配对后，`check_temporal_sync` 在真实数据上跑通；
- 新增 pytest 用例全绿；真实目录 `inspect_streams` 输出复核。

## 9. 已确认决策（2026-08-24）

1. **commit 拆分**：同意拆两个——A 语义识别内核（纯逻辑，不动工具接口），B 用户
   持久化层。边界清晰，便于分别评审与回滚。
2. **持久化位置**：`.dataset_profile.json` 写在项目 `outputs/` 下（按 dataset_id
   索引），不进数据集目录，集中管理。
3. **第 3 层实现**：验证逻辑作为 `_sniffing` 内部函数，在 load_dataset 嗅探流程内
   自动执行，结果写进流注册表的 `semantic_label` / `label_evidence` /
   `label_confidence`；`inspect_streams` 透出这些字段。不注册新 agent 工具，保持
   单 Agent + 工具循环结构。
4. **第 4 层入口**：用户质疑标签时，agent 用自然语言对话处理（沿用现有循环），确认
   结果经内部函数写 `.dataset_profile.json`；不需要专门工具。

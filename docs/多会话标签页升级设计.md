## 1. 问题（已核实代码）

### 1.1 现状实现

```125:145:streamlit_app.py
def _render_session_tabs() -> None:
    """顶部会话标签页：切换 / 关闭 / 新建。"""
    sessions = _sessions()
    active = st.session_state.active_session
    cols = st.columns([1] * len(sessions) + [0.6])
    for col, (tag, stt) in zip(cols, list(sessions.items())):
        with col:
            label = ("● " if tag == active else "") + stt["name"]
            if st.button(label, key=f"tab_{tag}", use_container_width=True):
                if tag != active:
                    st.session_state.active_session = tag
                    st.rerun()
            # 关闭按钮（小字）：关到最后一个时自动新建。
            if st.button("×", key=f"close_{tag}", help="关闭该对话"):
                _close_session(tag)
                st.rerun()
    with cols[-1]:
        if st.button("＋ 新建对话", key="new_session", use_container_width=True):
            _create_session()
            st.session_state.active_session = list(_sessions())[-1]
            st.rerun()
```

### 1.2 三个具体问题

**第一，标签一多挤成豆腐块。** `st.columns([1] * len(sessions) + [0.6])` 把可用
宽度**均分**给 N+1 列。开 6 个会话时每列约 1/7 宽；标签名形如
`● worldcode_ISuit-V3-01…`（`streamlit_app.py:178` 会截到 18 字符）加 `● ` 前缀，
在窄列内必然换行/省略，**关闭按钮 `×` 与标签挤在同一列内上下堆叠**，视觉混乱。

`docs/多会话设计.md` 第 6 节已承认此风险，当时决定"本次不做上限（用户自控）"。
但现在的问题是**不是上限，而是拥挤后的呈现**：没有优雅降级。

**第二，视觉上不像"标签页"。** 每个会话 = 2 个独立按钮（标签 + `×`）纵向堆叠，
N 个会话 = 2N 个按钮。用户无法一眼看出"当前在哪个标签"（只有 `●` 前缀暗示），
也没有下划线/底色等标签页惯用视觉线索。

**第三，切换触发整页 rerun。** 每次切标签 `st.rerun()`（`:136`）。功能正确
（状态在 session_state 中不丢），但配合 `_inject_scroll_css()` 的
`.block-container { overflow: hidden }`（`:47`）页面级滚动锁定，切换后的滚动位置
体验需实测；且 `st.rerun()` 是全脚本重跑，会话多时开销累积。

## 2. 设计

### 2.1 布局：固定宽度标签条 + 右侧独立操作区

```
┌──────────────────────────────────────────────────────────────────────┐
│ [● 对话 1] [对话 2] [对话 3] …  （横向滚动区）  │ ×关闭当前  ＋新建对话 │
└──────────────────────────────────────────────────────────────────────┘
```

- **标签条**：`st.columns([4, 1])` —— 左侧 4 份放标签（其内再横向排布/滚动），
  右侧 1 份放"关闭当前 / 新建"两个按钮；
- **每个标签只占一个按钮**（不再叠 `×`）；关闭入口收敛为**一个**"关闭当前会话"
  按钮（作用于 active）——这是主流浏览器标签页的心智（关闭当前），
  也把 N 个会话的控件数从 2N 降到 N+1；
- **当前标签的视觉**：`type="primary"` 用于 active 的按钮（Streamlit 原生的
  主色填充，天然区分），其余 `type="secondary"`。这比 `● ` 前缀更清晰，
  且**去掉 `● ` 前缀**可多显示几个字符的会话名；
- **标签名宽度**：保留现有"18 字符截断 + `…`"逻辑（`:178`），但截断长度按
  可用宽度动态化（见 2.2）。

### 2.2 拥挤的优雅降级（核心）

三种方案，**推荐方案 A**：

**方案 A（推荐）：横向滚动容器 + 固定标签宽**

```python
with st.container(horizontal=True, horizontal_alignment="left"):
    for tag, stt in sessions.items():
        label = stt["name"]
        if st.button(label, key=f"tab_{tag}", type=("primary" if tag == active else "secondary")):
            ...
```

- Streamlit 的水平容器（`st.container(horizontal=True)`，需 ≥1.31）内元素
  不压缩宽度，超宽时**容器内横向滚动**，标签不再变形；
- 缺点：需要横向滚动才能看到后面的标签（但**可读**优于**挤压变形**）。

**方案 B：折叠为下拉选择**

超过 N（如 5）个会话时，标签条改为 `st.selectbox` 选择会话 + 只显示当前标签名。

- 优点：任何会话数都不挤压；
- 缺点：切换多一步（点开下拉），且失去"一眼看到所有会话"的能力。

**方案 C：标签数量硬上限**

超过 N 个时禁止新建（提示"请先关闭部分会话"）。

- 优点：实现最简单；
- 缺点：限制用户，与 `多会话设计.md` "不做上限（用户自控）"的决策冲突。

**决策建议**：**A 为主**（保可读性、不限制用户）。若 owner 偏好"永不滚动"，
则用 B（会话数 > 5 时自动切换下拉）。

### 2.3 关闭交互

- **关闭当前**：一个按钮，禁用条件为"只剩 1 个会话"（避免"关了又自动新建"的
  隐晦行为）——现有 `_close_session` 在关到最后一个时会自动新建
  （`:100-108`），保留该兜底，但**按钮在只剩 1 个时 disabled + tooltip
  "至少保留一个对话"**，让行为可预期；
- **关闭非当前会话**：主流浏览器标签支持，但需要每标签一个关闭控件（回到 2N 按钮）。
  **不做**——用户可先切过去再关；这是对"控件数"与"便利性"的取舍，选前者；
- `_close_session` 逻辑不动（已正确：关到最后一个自动新建）。

### 2.4 切换的性能（可选优化）

现状 `st.rerun()` 全脚本重跑。可选优化：切换时**只改 `active_session`
不 rerun**，依赖 Streamlit 下一次自然重跑生效。

- **风险**：Streamlit 的按钮回调后若不 rerun，本次已渲染的仍是旧会话内容，
  用户看到"点了没反应"（要再点一次）——体验更差。
- **决策**：**保留 `st.rerun()`**。原因是正确性优先；性能优化需实测确认
  Streamlit 语义后再做，不属本次范围。

## 4. 测试计划

**UI（AppTest）**
- 新建：标签数 +1，新会话 messages 为空（**保留现有用例**）；
- 切换：历史/数据集状态保留（**保留现有用例**）；active 标签的 `type` 为 primary；
- 关闭当前：标签数 -1；只剩 1 个时关闭按钮 disabled；
- 关到最后一个自动新建（**保留现有用例**）；
- 切换标签**不触发 agent**（**保留现有用例**，`多会话设计.md` 5 节规定）。

**结构断言**
- `_render_session_tabs` 内按钮数 == 会话数 + 2（N 个标签 + 关闭当前 + 新建），
  防回归到"2N 个按钮"形态。

**人工验收**
- 开 6 个会话（含长数据集名）：标签可读、可横向滚动、当前标签视觉清晰、
  切换与关闭均正常。

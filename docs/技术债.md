## 2. IMU 通道饱和削顶检测（check_sensor_sanity）

- **状态**：已完成（2026-08-20）
- **问题**：`check_sensor_sanity` 的量程饱和削顶检测目前仅覆盖力/力矩流，不覆盖 IMU 的
  陀螺仪/加速度计通道。快速运动下陀螺仪饱和削顶是真实高频问题，应扩展检测。
- **处理**：`check_sensor_sanity` 已扩展削顶检测到 IMU 的陀螺仪/加速度计通道，复用
  `_saturation_ratio` 辅助函数，返回 `saturation_check`（accel/gyro 饱和比例 + 阈值），
  超阈判 fail。回归 `tests/test_check_sensor_sanity.py::test_imu_gyro_saturation_detected`。
- **优先级**：高（快速运动下陀螺仪削顶是真实高频问题）。

## 3. 第 3 层 LLM 语义假设通道未接模型

- **状态**：已评估 - 按架构决策实施中（2026-08-24 记录；2026-08-27 更新状态与触发条件，
  见 ARCHITECTURE.md 3.3.1 数据识别架构）
- **问题**：四层语义识别架构中，第 3 层"LLM 语义假设 + 工具验证"目前没有接入任何
  模型，仍是第 1 层词典线索与第 2 层内容指纹的纯规则裁判（`classify_table_stream`）。
  当真实数据出现内容指纹无法分类的流时，该流被标为 `unknown（无法分类）`，
  缺少 LLM 这一层"语义假设 + 工具验证"的兜底，只能依赖第 4 层用户确认。
- **触发条件**（2026-08-27 更新）：**语义角色规则无法覆盖的 unknown 标签**——即
  `classify_table_stream` 走完第 1 层词典线索与第 2 层内容指纹仍返回 `kind="unknown"`
  的流；且目录结构有公开格式特征、LLM 有合理先验。数值计算类判定（单位换算、采样率、
  对齐残差）**不适用**本通道——必须由工具确定性完成。
- **处理约定**：`classify_table_stream` 在判不出时**显式返回 unknown + 置信度说明**
  （label_evidence 列出已排查的词典与指纹层级），绝不硬猜。SYSTEM_PROMPT 纪律第 9 条
  已落地（假设须标注"假设"+证据+"未经工具验证"，主动请用户确认，确认后经
  confirm_stream_semantic 落盘）；行为测试.md 已固化「假设标注纪律」终身回归用例。
  后续如做工具级自动验证，应以工具回读（列名/样本分布）验证假设，验证通过再写
  `semantic_label` + `label_evidence` + `label_confidence`。
- **优先级**：低（架构决策已定，prompt 级已实施；剩余为可选的工具级自动验证增强，
  仅在语义角色规则覆盖不足的真实需求出现后再评估）。

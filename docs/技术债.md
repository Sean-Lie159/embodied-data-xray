## 1. `app/agent/agent.py` 既有 lint 报错清理

- **状态**：已完成（2026-08-21）
- **问题**：基于 pyright 严格检查的既有报错，多为历史遗留，非本轮引入：
  - `MaxTurnsExceeded` 分支的返回类型不匹配（`tuple[str, list[Any], None]`，line ~105）。
  - `RunContextWrapper` / `Any` 显式类型（`reportExplicitAny` / `reportAny`，line 11 / 44 / 66 / 68 / 87 / 102 / 109 等）。
  - `SYSTEM_PROMPT` 隐式字符串拼接（`reportImplicitStringConcatenation`）。
- **处理**：
  - `run_turn` 返回值改为精确联合类型 `RunTurnResult = tuple[str, list[TResponseInputItem], RunResult | None]`，`None` 分支显式返回。
  - 收紧 `Any`：`build_agent` 的 `tools` 用 `list[Tool]`、`history_input` 用 `list[TResponseInputItem]`、`_extract_tool_name` 的 `item` 用 `RunItem`；`raw_item` 用 `cast` 声明类型。
  - `MaxTurnsExceeded` 分支的隐式字符串拼接改用 `+` 显式拼接；`SYSTEM_PROMPT` 本身已是单一三引号字符串，无隐式拼接，未改写文案。
  - `final_output` 在 SDK 中类型标注为 `Any | None`，无法泛型收紧，用 `str()` 转换并用 `# pyright: ignore[reportAny]` 抑制。
- **验证**：`basedpyright` 对 `agent.py` 检查归零；完整测试套件 `120 passed, 1 skipped`；CLI 真实对话一轮跑通（final 提取 / next_input / RunResult 均正常）。
- **遗留**：~~`run_turn` 在 `MaxTurnsExceeded` 时返回 `result=None`，调用方未处理 `None`~~（已于 2026-08-21 跟进修复：`run_turn` docstring 明确 `result=None` 契约；`chat_service._extract_tool_names` 显式判空返回空列表；`main.py` 经 `format_tool_activity` 判空天然健壮；新增 `tests/test_main.py` 与 `test_chat_service.py::test_areply_handles_max_turns_exceeded`，并经极小 `max_turns` 实测触发该路径确认输出友好提示而非 traceback）。

- **优先级**：高（快速运动下陀螺仪削顶是真实高频问题）。

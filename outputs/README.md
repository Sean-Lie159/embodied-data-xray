# outputs/ — Agent 运行产物目录

本目录存放 **Embodied-data-Xray 运行过程中生成的一切产物**。

- 本目录已在 `.gitignore` 中排除，**不会进入 git**；
- 可以随时整个删除（下表中的"示例数据集"与"上传文件"会一并删除，需要时重新生成/上传即可）。

## 目录结构

```
outputs/
├── by_dataset/                      # 按数据集归类（每个数据集一个子目录）
│   └── <数据集名-短哈希>/
│       ├── charts/                  # 图表 png
│       │   └── <会话前缀><数据集>_<图类型>_<时间戳>.png
│       ├── reports/                 # Markdown 报告
│       │   └── <会话前缀><数据集>_report_<时间戳>.md
│       └── profile.json             # 该数据集的语义确认画像（跨会话生效）
├── _misc/                           # 未加载数据集时产生的产物（兜底）
│   ├── charts/
│   └── reports/
├── uploads/                         # 通过界面上传的数据文件原文
├── sample_dataset/                  # 内置示例数据集（可删除，会重新生成）
└── mcap_unpack/                     # MCAP 解包产物
```

## 说明

**为什么按数据集分子目录**：同一数据集多次分析会产生多个图表与报告，
集中到该数据集的目录下便于查找与清理（删除某数据集目录即清掉它的全部产物）。

**子目录名里的短哈希**：数据集名过长会被截断，末尾 6 位哈希保证两个不同的
长名字不会落到同一个目录。它只影响目录名（供人查看），不影响任何程序逻辑。

**文件名的会话前缀**：形如 `s-1a2b_`。当你在界面上开多个对话同时分析**同一个
数据集**时，靠这个前缀避免两会话的产物互相覆盖。

**profile.json 是什么**：记录你对"这条流是什么语义"的确认结果。它是**跨会话
生效**的——下次再加载同一数据集时自动应用，不需要重新确认。如果你想撤销某个
确认，可以编辑该文件，或让它重新走一次确认流程。

**旧版本兼容**：早期版本的确认记录集中在单个 `.dataset_profile.json` 文件中；
升级后首次读取会自动迁移到新位置（每个数据集一个 profile.json 文件），
旧文件保留不删。
